# Internationalization

Ronin's lobby and game client speak Japanese (`ja`), English (`en`) and Russian (`ru`). This file is
the contract every translated string follows: how the language is chosen, how catalogs are written,
and the one glossary every game term is spelled from.

The ja and ru catalogs are machine drafts checked by the implementer against this glossary.
**Native-speaker review is deferred**: no catalog has had one, and nothing may claim it happened.
The automated catalog check (`bin/check_i18n.py`, run by `make lint`) and visual review of every
translated screen are required; native review is not a completion gate.

## Locales and resolution

* Supported: `ja`, `en`, `ru`. Default and fallback: `en` in every app. Language choices are shown
  by their native names: English, 日本語, Русский.
* One order everywhere:
  1. the `lang` cookie, when its value is exactly one of the supported codes (anything else is
     ignored);
  2. else the browser preference: `Accept-Language` on the server (q-value order, ties in header
     order), `navigator.languages` in the game client (list order); each entry matched by its
     primary subtag, case-insensitive (`ja-JP` → `ja`, `RU` → `ru`); the first supported wins; `*`
     is ignored;
  3. else `en`.
* Server-rendered lobby pages resolve on the server and print `<html lang="…">`; the lobby scripts
  read that attribute and never resolve on their own. The game client resolves once, in
  `public/locale.js`, a classic script ahead of its bundle, onto `<html lang>`, which the bundle
  reads. Auto-detection never writes the cookie.
* A lobby HTML response whose language did not come from the cookie carries
  `Vary: Accept-Language, Cookie`.

## The `lang` cookie

* `lang=<ja|en|ru>; Path=/; Max-Age=31536000; SameSite=Lax`, plus `Secure` when the lobby's
  `cookie_secure` is on (in the game client: when the page is served over `https:`).
* **Not HttpOnly**: the game client reads it. It carries no credential; it is the one exception to
  the lobby's HttpOnly cookie rule.
* Written only by an explicit choice: the lobby's `POST /lang` (the nav's language menu) and the
  game client's settings menu. Both use the same name, path and attributes, so they overwrite one
  cookie. Every reader validates the value against the allowlist.
* There is no account field: the language lives in the cookie only.

## Catalogs

| App | Catalogs |
|---|---|
| lobby server | `backend/lobby/i18n/locales/{en,ja,ru}.json` |
| lobby scripts | `frontend/lobby/src/i18n/locales/{en,ja,ru}.json` |
| game client | `frontend/game/src/i18n/locales/{en,ja,ru}.json` |

Apps share nothing at build time: a sentence two apps need is duplicated in each.

* One flat JSON object per locale, dotted keys grouped by screen (`nav.history`, `room.seat.open`,
  `yaku.12`), sorted by key. en is the source: a key is added to en first.
* Values are plain text. No HTML: `<` followed by a letter or `/` is rejected.
* Placeholders are `{name}` with `name` matching `[a-z][a-z0-9_]*`. Literal braces are not
  supported. Every locale of a key has the same placeholder set.
* **Plurals**: the value is an object keyed by CLDR cardinal categories, exactly `one`, `other` (en);
  `one`, `few`, `many`, `other` (ru); `other` (ja). The count is always the `{count}` param, formatted
  with the locale's number format, and en carries `{count}` in a category. Python picks the category
  with a hand-written rule (en: `n == 1`; ru: one if n%10 == 1 and n%100 != 11, few if n%10 in 2..4
  and n%100 not in 12..14, else many); JavaScript with `Intl.PluralRules(locale)`. `count` is reserved
  for plurals.
* **Link slots**: a sentence containing a link is one key whose link position is a placeholder,
  with the link's text as its own key: `auth.login.no_account` = "Don't have an account?
  {register}", `auth.login.register_link` = "Register". Translators may move the slot anywhere. The
  call site passes a rendered element for the slot (Jinja: a `Markup` built with
  `{% set %}…{% endset %}`; lit-html: `tParts`; game JS: `tNodes`). Where a slot sentence would be
  awkward, write a separate complete sentence plus a standalone link. Never split a sentence into
  "before" and "after" keys.
* Numbers go through the locale's number format: ru groups with a space (the lobby server with
  U+202F narrow no-break space, `25 000`; the frontends with whatever `Intl.NumberFormat("ru")`
  uses, U+00A0 in current engines), en and ja with commas (`25,000`). Dates, times and lists use an explicit locale
  (`Intl.DateTimeFormat`, `Intl.ListFormat(locale, {type: "conjunction"})`).

### Strictness

A key missing from the catalog, a placeholder with no param, a param the value does not use, a
plural key called without a numeric `count`, or a non-plural key given a `count` is an i18n error.
Params are validated against the en value (the check guarantees every locale has the same set).

* Strict (throws): the lobby server when `APP_VERSION == "dev"` (tests and local runs); the
  frontends under `import.meta.env.DEV` (Vite dev server and Vitest).
* Production: render the en value (or the key itself if en lacks it) and report once per distinct
  key: `logger.warning("i18n error", …)` on the server, one `reportI18nError` (`console.error`) per
  frontend app.
* Dynamic keys (`auth.error.<code>`, `room.error.<code>`, `yaku.<id>`, …) cannot be proven by a
  static scan: each family has one test that walks its whole domain in strict mode, and an unknown
  code at runtime takes the family's generic key and reports the code.

### The catalog check

`bin/check_i18n.py` (stdlib only, run by `make lint`) fails on differing key sets, differing
placeholder sets, wrong plural shapes, empty values, HTML, an unsorted or invalid file, a literal
key used in code but absent from en, an en key used nowhere and outside the script's dynamic-prefix
allowlist, and a ja or ru value identical to en outside its identical-value allowlist.

## Rules for text

* **What is translated**: every user-visible UI string of the lobby pages, the lobby scripts and the
  game client. Bot JSON API errors, plain-text and JSON error answers, WebSocket protocol errors and
  log text stay English. Server errors travel as codes and are translated by the client; server
  English never appears in translated UI.
* **Identities are never translated**: bot (`Tsumogiri Bot N`), guest (`Nanashi-NNNN`), player and
  room names are shown exactly as they are; user chat is never translated. Only the labels and
  system messages around them are.
* **Storybook sample prose stays English**; real components in a storybook follow the locale.
* **ja tone**: です/ます sentences; noun labels on buttons and headings, except where a concise
  conventional action label says better what a click does (ログイン, 参加する). No honorific
  embellishment, no literal English sentence structure.
* **en**: sentence case for UI prose and labels; game terms in romaji as in the glossary (yaku names
  in title case). Two mixes are deliberate and match riichi.wiki: draws named after a hand or yaku are romaji (Nagashi
  Mangan, Kyuushu Kyuuhai) and the rest plain English (Four riichi, Four kans, Four winds, Triple ron); a romanized
  four-kan draw would be "Suukan Sanra", the reading of our 四槓散了, never "Suukaikan". Winds are English (East,
  Seat Wind East) while dragons are romaji (Haku, Yakuhai Haku); their spoken names are English for all seven.
* **ru**: game terms in Cyrillic transliteration (community spellings, чи not ти), one spelling per
  term as below; plain Russian for UI prose and for draw explanations whose term is opaque; Russian
  plural forms wherever a count appears. Prefer wording that does not mark the player's gender
  (Готовность подтверждена, not Готов; Игрок {name} вышел; Объявлено: {players}, not Объявил). Transliteration rules
  used for the glossary: sh → ш, ch → ч, j → дж, ts → ц, standalone e → э, ei → ей, ou → о, uu → у, ii → ии, aa →
  аа. One exception: the call チー is Чи (Tenhou ru's spelling), although the same チー is Чии in Чиитойцу and Чиихо.
  хонба is indeclinable: a sentence that would decline it is reworded ("(хонба +300)", not "за хонбу").
* **han, fu and every term are spelled identically** across yaku, narration, results and help.
* **Tiles**: compact localized names in visible text (replay narration), full spoken names in
  `alt`/`aria-label`. Tile-face art, the nameplate wind markers and the loading screen's 東 mark
  stay kanji.
* **Rounds and winds in text** are localized: 東一局 1本場 / "East 1, 1 honba" / "Восток 1, 1 хонба".
